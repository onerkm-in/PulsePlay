Executive Summary

PulsePlay has built a well-structured internal design system (--pp-* tokens, styles.css, settings.css) that is thorough and internally consistent — but it is an entirely separate design language from Industry. The Industry DS bundle is never loaded in the app. Every foundational element — typeface, colour accent, border radius, card treatment, icon library, blueprint framing — diverges from Industry's specification. The result is a product that reads as a generic SaaS dashboard (rounded cards, Inter typeface, bright-blue accent, heavy shadows, pill chips) when it should read as a precision wireframe instrument (square-cornered blueprint cards, Barlow Condensed, steel-blue, registration marks, hairline borders).

The gap is not a polish issue — it is a foundational one. Closing it requires replacing --pp-* token values to match Industry's --color-*, swapping the typeface import, removing all rounded-corner rules, applying the .blueprint frame to every card and primary button, and switching to Lucide icons at stroke-width 1.5.

Critical Findings

These break the design system contract at the foundation level. Every other surface inherits these failures.

Critical
Industry DS bundle never loaded
playground/index.html · playground/src/styles.css
▾

The Industry design system provides its tokens, component classes, and typeface imports through styles.css and _ds_bundle.js. Neither file is referenced anywhere in PulsePlay's index.html, styles.css, or any component. The app runs entirely on its own hand-rolled --pp-* token system. Every other finding below is a consequence of this root absence — if the bundle were loaded, most tokens would resolve correctly.

Current — styles.css :root
/* No import of Industry bundle */
--pp-accent: #2563eb;
--pp-font: "Inter", "Segoe UI", system-ui;
--pp-radius: 10px;
Required — every entry point
<link rel="stylesheet" href=
  "_ds/industry-.../styles.css">
<script src=
  "_ds/industry-.../_ds_bundle.js">
</script>
FixAdd the Industry stylesheet and bundle to index.html before PulsePlay's own styles.css. Then remap the --pp-* tokens to alias the Industry --color-*, --font-*, --space-* variables so existing component CSS picks up the correct values with minimal churn.
Critical
Wrong typeface — Inter instead of Barlow
playground/src/styles.css · workbench.css · settings.css
▾

Industry mandates Barlow Condensed for all headings and Barlow for body text. PulsePlay uses Inter (the most common "AI slop" font) across every surface. The workbench additionally falls back to -apple-system, BlinkMacSystemFont, Segoe UI, Roboto, Helvetica, Arial — not Barlow at any point. The typographic character of Industry (technical, condensed, structured) is entirely absent.

Current
--pp-font: "Inter", "Segoe UI",
  -apple-system,
  BlinkMacSystemFont,
  system-ui, sans-serif;

/* Workbench */
font-family: -apple-system,
  BlinkMacSystemFont, "Segoe UI",
  Roboto, Helvetica, Arial,
  sans-serif;
Required
/* Industry provides via styles.css */
--font-heading: "Barlow Condensed",
  system-ui, sans-serif;
--font-body: "Barlow",
  system-ui, sans-serif;

/* Remap pp tokens */
--pp-font: var(--font-body);
/* All h1-h4: font-family: var(--font-heading) */
FixIndustry's styles.css imports Barlow and Barlow Condensed from Google Fonts. Once the bundle is loaded, set --pp-font: var(--font-body) and ensure all heading elements use font-family: var(--font-heading). Remove the Inter import.
Critical
Wrong colour accent — #2563eb vs steel-blue #5980a6
playground/src/styles.css (all surfaces)
▾

The Industry accent is a muted steel-blue #5980a6. PulsePlay uses a bright saturated blue #2563eb that reads as a generic SaaS primary — visually loud, high-chroma, and completely different in character. The settings header icon compounds this with a purple gradient (linear-gradient(135deg, #2563eb 0%, #7c3aed 100%)). Industry's system is intentionally mono: one accent, no second colour.

Current
--pp-accent:       #2563eb;
--pp-accent-hover: #1d4ed8;
/* Settings icon */
background: linear-gradient(135deg,
  #2563eb 0%, #7c3aed 100%);
Required
--color-accent: #5980a6;
/* Ramp steps for states */
hover:  var(--color-accent-600)
active: var(--color-accent-700)
/* No purple, no gradient accents */
FixReplace --pp-accent with var(--color-accent) and all accent state variants with the appropriate ramp step (--color-accent-600 for hover, --color-accent-700 for pressed). Remove all purple values. Remove the gradient from the settings header icon.
Critical
Blueprint treatment entirely absent
All card surfaces, primary buttons, figures
▾

Industry's defining visual signature is the blueprint frame: every card, figure, and primary button wears the .blueprint class plus four <i class="corner tl/tr/bl/br"> registration marks. These hairline crosshairs at each corner give the design its "technical instrument" character. PulsePlay has zero instances of this pattern — no .blueprint class, no corner marks, no registration marks of any kind. Cards are plain rounded white boxes. The entire visual identity of Industry is missing.

Current — pp-assistant-empty card
<div class="pp-app__empty">
  <!-- plain div, no frame -->
  <h2>Ask Pulse</h2>
  ...
</div>
Required — Industry card
<div class="card blueprint">
  <i class="corner tl"></i>
  <i class="corner tr"></i>
  <i class="corner bl"></i>
  <i class="corner br"></i>
  <p class="card-kicker">Surface</p>
  <h3 class="card-title">Ask Pulse</h3>
  ...
</div>
FixApply .card.blueprint + four corner <i> elements to every card surface: empty states, launchpad asset cards, wizard persona cards, settings groups, workbench artifact cards. The .blueprint CSS is provided by Industry's styles.css — it only needs the markup.
Critical
Wrong background + surface colours
playground/src/styles.css · settings.css
▾

Industry's ground is a warm off-white #f2f2f3 (slightly warm, not cool). PulsePlay uses #f4f6f9 — a cool blue-grey that doesn't match Industry's neutral ground. The surface colour is #ffffff in PulsePlay vs Industry's #e9e9ea. These are not subtle differences — they shift the entire tonal feel of the product from Industry's "light technical ground" to a cool cloud SaaS palette.

Current
--pp-bg:      #f4f6f9;  /* cool blue-grey */
--pp-surface: #ffffff;  /* pure white */
--pp-text:    #0f172a;  /* very dark navy */
Required (Industry)
--color-bg:      #f2f2f3; /* warm off-white */
--color-surface: #e9e9ea; /* slightly deeper */
--color-text:    #1d1f20; /* near-black */
FixRemap --pp-bg → var(--color-bg), --pp-surface → var(--color-surface), --pp-text → var(--color-text) once the Industry bundle is loaded.

High Findings

Component-level violations that contradict specific Industry rules on every rendered surface.

High
Rounded corners everywhere — Industry requires square
styles.css · settings.css · workbench.css (all components)
▾

Industry's design guide is explicit: "Do not round cards, figures or buttons." All components use border-radius: 0 (with a max of 4px on --radius-md for inputs). PulsePlay uses aggressive rounding throughout: cards at 6–12px, buttons at 7–8px, inputs at 10px, chips at 999px (pill), settings chips at 999px, search bar at 10px, and the floating toolbar is pill-shaped. The pill shape (border-radius: 999px) appears on at least 14 distinct component types — it is the most repeated Industry violation in the codebase.

Current — radius values in use
--pp-radius-xs:   4px
--pp-radius-sm:   6px
--pp-radius:      10px  /* inputs */
--pp-radius-lg:   14px  /* cards */
--pp-radius-xl:   20px
--pp-radius-pill: 999px /* chips, tags */
/* settings chips: border-radius: 999px */
/* allowlist chip: border-radius: 999px */
/* surface-mode chip: border-radius: 999px */
/* setup pill: border-radius: 999px */
/* combobox: border-radius: 7–8px */
Required (Industry)
--radius-sm: 2px
--radius-md: 4px  /* inputs, buttons */
--radius-lg: 7px  /* dialogs only */
/* Cards: border-radius: 0 (blueprint) */
/* Tags: border-radius: 3px (0.75×radius-md) */
/* No 999px pill shapes */
FixDo a global replace: all border-radius: 999px → border-radius: var(--radius-md). Cards → 0. Inputs and buttons → var(--radius-md). Convert pill-shaped chips/tags to Industry's .tag class (already square-cornered in the DS).
High
Cards have filled surfaces — Industry cards are transparent
styles.css · settings.css · FirstRunWizard.tsx
▾

Industry cards are line drawings — background: transparent, hairline border. PulsePlay cards are filled white boxes (background: #ffffff, box-shadow: 0 4px 12px …). The persona cards in the First-Run Wizard compound this with gradient fills (linear-gradient(135deg, #eff6ff 0%, #dbeafe 100%) for Analyst, #f5f3ff → #ede9fe for Executive). Industry forbids both the fill and any gradient beyond the accent.

Current — pp-app__empty
background: var(--pp-surface-raised, #fff);
border: 1px solid var(--pp-border, #e4e9ef);
border-radius: 6px;
box-shadow: rgba(0,0,0,.04) 0 1px 2px 0;
Required
background: transparent;
border: 1px solid var(--color-divider);
border-radius: 0;
/* elevation only via .elev-sm/md/lg */
FixSet all card backgrounds to transparent. Remove gradient fills from wizard persona cards — use a .tag-accent kicker label instead of a coloured card background to differentiate personas. Elevation = .elev-sm class only.
High
Gradients used decoratively throughout — Industry forbids them
styles.css · settings.css · FirstRunWizard.tsx
▾

Industry adds zero decorative colour beyond the steel accent. PulsePlay uses gradients in at least five places: (1) brand heading text (linear-gradient(135deg, #0f172a 0%, #4f46e5 100%) with -webkit-background-clip: text), (2) settings header icon (linear-gradient(135deg, #2563eb 0%, #7c3aed 100%)), (3) form input/select backgrounds (paper texture gradient), (4) wizard persona card fills (blue, purple, cyan, pink gradients per persona), (5) settings back-button inset highlight. Industry's only permitted "field" is a full --color-accent-900 block for section dividers in decks.

FixRemove all decorative gradients. Brand heading: use font-family: var(--font-heading) in plain var(--color-text). Settings icon: replace with a Lucide icon in accent colour. Form inputs: solid var(--color-surface) background. Persona cards: transparent blueprint cards with a .tag-accent kicker.
High
Custom SVG icons at stroke-width 1.8–2 — Industry requires Lucide at 1.5
TopRightToolbar.tsx · SurfaceSwitcher.tsx · AssistantEmptyState.tsx
▾

Industry specifies Lucide icons at stroke-width 1.5 throughout. PulsePlay draws all its icons as bespoke inline SVGs with strokeWidth={1.8} to strokeWidth={2}. The shapes also differ from Lucide's (e.g. the sparkle path in SurfaceSwitcher is a custom 4-point star, not Lucide's Sparkles; the alert triangle doesn't match Lucide's AlertTriangle). Heavier strokes make the icons look less technical — the opposite of Industry's intended "thin-stroke" character.

Current — SurfaceSwitcher.tsx
const common = {
  strokeWidth: 2,    /* too heavy */
  ...
}
/* Custom sparkle path: */
<path d="M12 3 L14 10 L21 12..." />
Required — Lucide via CDN or npm
<!-- CDN example -->
<i data-lucide="sparkles"
   style="width:14px;height:14px;
   stroke-width:1.5"></i>

/* Or lucide-react */
import { Sparkles } from "lucide-react";
<Sparkles size={14} strokeWidth={1.5} />
FixAdd lucide-react (already a near-zero-weight tree-shakeable package). Replace every custom SVG in TopRightToolbar, SurfaceSwitcher, and all other components with the matching Lucide icon at size={14} strokeWidth={1.5}.
High
Shadow scale too heavy — Industry uses hairline + subtle elevation
styles.css (--pp-shadow-* tokens)
▾

PulsePlay defines 5 shadow levels up to 0 16px 48px rgba(15,23,42,.16). Industry defines 3 subtle levels maxing at 0 12px 32px color-mix(in srgb, #2b2b2d 22%, transparent) — and the DS guide specifically warns against "soft filled rounded blocks" that rely on shadow for depth. The combination of filled cards + heavy shadows is doubly wrong.

Current
--pp-shadow-xl: 0 16px 48px
  rgba(15,23,42,.16),
  0 8px 16px rgba(15,23,42,.08);
/* 5 levels: xs sm md lg xl */
Required (Industry)
--shadow-sm: 0 1px 2px …14%
--shadow-md: 0 3px 10px …16%
--shadow-lg: 0 12px 32px …22%
/* Used sparingly via .elev-sm/md/lg */
FixOnce blueprint cards have transparent backgrounds, most shadows become unnecessary. Keep three levels. Use .elev-sm for popovers/dropdowns only. Remove --pp-shadow-xl entirely.
High
Navigation bar unstyled by Industry — missing .nav / .nav-brand
styles.css (.pp-top-bar) · App.tsx
▾

Industry provides a .nav + .nav-brand header bar pattern. PulsePlay's top bar uses a custom .pp-top-bar class with no relation to Industry's navigation component — a white surface with box-shadow, the brand title rendered with a gradient clip-text effect, and pill-shaped status chips in the top right. Industry's nav is a clean, flat bar: condensed-heading brand mark, link items, and one accent CTA.

FixRebuild the top bar using Industry's .nav class. Brand name uses .nav-brand (Barlow Condensed, no gradient). Status indicators use .tag classes. Remove the gradient text effect from the h1.

Medium & Low Findings

Medium
Emoji used as icons and decorative elements
AssistantEmptyState.tsx · FirstRunWizard.tsx · settings.css
▾

Industry specifies no emoji unless the brand uses them. PulsePlay uses ✨ in AssistantEmptyState, 📊🎯🛠️🎨 as persona icons in the First-Run Wizard, and a colour-gradient emoji-styled icon in the settings header. These read as consumer app / chatbot UI, not a precision analytics instrument.

FixReplace all emoji with Lucide icons: Sparkles for empty states, BarChart2 / Target / Wrench / Palette for wizard personas. Use the icon in accent colour within a blueprint-framed container rather than as freestanding emoji.
Medium
Spacing scale uses 4px base — Industry is 0.85× (3.4px) density
styles.css (--pp-s* tokens)
▾

Industry's spacing scale is baked at 0.85× density: --space-1: 3.4px, --space-2: 6.8px, --space-3: 10.2px, --space-4: 13.6px. PulsePlay uses a standard 4px grid. The result is that PulsePlay surfaces feel slightly looser than Industry's intended analytical density.

FixRemap --pp-s1→--pp-s8 to var(--space-1)→var(--space-8) once the Industry bundle is loaded. Components that currently feel spacious will tighten appropriately.
Medium
Dark mode entire system — not in Industry DS
styles.css (:root[data-pp-theme="dark"])
▾

Industry does not specify a dark mode — it is a light-ground system. PulsePlay has an extensive dark theme (data-pp-theme="dark") with ~100 token overrides across styles.css and settings.css. If PulsePlay needs dark mode, the team needs to extend Industry's token set with a documented dark ramp — not invent a parallel system.

FixDecide whether dark mode is a product requirement. If yes, design it as a named extension of Industry (dark ground ramp from the neutral-900 step), document it, and keep it in sync with the DS. If dark mode is optional/experimental, gate it clearly and don't let it drive token decisions in the light theme.
Medium
Focus ring uses wrong accent colour
styles.css · settings.css (all interactive elements)
▾

Industry specifies :focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px; } — steel-blue. PulsePlay's focus rings use rgba(37, 99, 235, 0.18) (bright blue) plus a box-shadow glow. When the accent is corrected, the focus rings will also correct automatically if they reference the token — but inline rgba(37, 99, 235, …) values won't.

FixReplace all hardcoded rgba(37, 99, 235, …) focus-ring values with var(--color-accent). Remove the box-shadow glow from focus states — Industry uses a clean 2px outline only.
Low
Form inputs use paper-texture gradient background
styles.css (.pp-vendor-picker__select, .pp-embed-config__input)
▾

Textareas use a ruled-paper repeating gradient (repeating-linear-gradient(180deg, transparent 0, transparent 27px, rgba(15,23,42,0.03) 28px)). Industry inputs are flat var(--color-surface) — no decorative texture.

FixSet all form control backgrounds to var(--color-surface). Remove the paper-texture gradient. Inputs should feel like technical form fields, not notepads.
Low
Settings back-button has animated translateX transform hover
settings.css (.pp-settings-header__back)
▾

The back button slides left on hover (transform: translateX(-2px)). Industry interaction states are purely colour-based (accent ramp tint on hover, deeper step on press) — no movement or animation beyond colour transition. This kind of micro-animation makes the UI feel playful rather than precise.

FixRemove the translateX hover. Replace with a background tint from the accent ramp (var(--color-accent-100) on hover, var(--color-accent-200) on press).

Decision Assist — Worst-Offending Surface

Three files — DecisionCanvasShell.tsx, DecisionPromptCard.tsx, and ActionInsightsPanel.tsx — were not captured in the surface matrix above but are the most severe compliance failures in the entire codebase. Unlike other surfaces that at least use --pp-* CSS tokens, these three use 100% raw inline styles with hardcoded hex values. No CSS class, no design token, no Industry component is used anywhere in them.

Critical
All three Decision screens: pure inline styles, zero token usage
DecisionCanvasShell.tsx · DecisionPromptCard.tsx · ActionInsightsPanel.tsx
▾

This makes the surface invisible to theme changes, impossible to systematically restyle, and immune to any DS remediation applied elsewhere.

What Not To Build

Pattern in PulsePlay todayWhy it conflicts with Industry
Pill-shaped chips / tags (999px radius)Industry tags are near-square — the pill reads as consumer chat UI, not analytical instrument
Gradient text on headings (clip-text)Industry headings are flat Barlow Condensed in --color-text — no colour effects
Filled white cards with box-shadowsIndustry cards are transparent wireframe line-drawings
Multi-colour accents (purple #7c3aed, cyan #0891b2)Industry is mono — one steel-blue accent, no second hue
Emoji as UI iconsIndustry uses Lucide thin-stroke icons exclusively
Heavy entrance animations / translateX hoversIndustry interaction states are colour-only (ramp tint on hover)
Paper-texture gradient in textareaIndustry form inputs are flat solid-surface — no decorative texture
5-level shadow scale with xl/2xlIndustry uses 3 levels, sparsely — most surfaces need none once cards are transparent
